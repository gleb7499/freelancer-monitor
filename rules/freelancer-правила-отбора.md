# Freelancer.com — Правила отбора заказов (единый источник правды)

> Дата: 2026-10-03. Канал — только alerts (saved-search alerts). Search-линия удалена.
> Парсер: публичный JSON API (`/api/projects/0.1/projects/`), HTML-дампы не нужны.
> Ставки — официальный API `POST /api/projects/0.1/bids/` с OAuth-токеном.
> Значения в таблицах вынесены так, чтобы их можно было менять одной правкой.

---

## Все правила (кодовые фильтры — не переоценивать)

| Правило | Значение | Где применяется |
| --- | --- | --- |
| Язык заказа | английский; остальные — пас | Код |
| Явный фуллтайм | пас | Код (`upgrades.fulltime`) |
| Bids у заказа | код отсекает заказы с bids > 10 до LLM | Код |
| Оплата клиента | в данных заказа поле `client`: payment_verified/deposit_made/рейтинг/число открытых заказов. Данные есть — учитывай напрямую. `client` пуст — надёжность оплаты неизвестна: это фактор риска для твоей оценки (value_score/red_flags/check_manually), но вердикт BID/PASS — всё равно твой, автоматического BID или PASS из-за отсутствия данных нет | LLM-скоринг |
| Бесплатные тесты | запрещены — пас | LLM-скоринг |
| Дедлайн короче 7 дней при объёме более 30 ч | показывать с оговоркой «+дни до контракта» | LLM-скоринг |
| Пограничные / неясные случаи | показывать всегда; скрывать только при явном НЕТ | LLM-скоринг |

> **Конкуренция кодом НЕ оценивается и в LLM не передаётся.** Старые tier-правила
> (normal/high) и скидочная механика от конкуренции отменены — конкуренция режется
> жёстким фильтром bids > 10 до скоринга.

## Что оценивает LLM — ТОЛЬКО два критерия

### 1. Бюджет через value-score

LLM оценивает **только** целесообразность цены. Механика:

1. Оцени `ai_hours` — часы работы с учётом того, что исполнитель работает с роем
   AI-агентов (быстро). **Упоминать AI-агентов / AI-ускорение в любом поле,
   читаемым клиентом, ЗАПРЕЩЕНО.**
2. Ставка предлагается **в валюте заказа** (`currency_code`; родная вилка —
   `budget_min_original`/`budget_max_original`) **круглой суммой**. Код
   восстанавливает курс из бюджета (`budget_min_original / budget_min`) и
   пересчитывает суммы в USD.
3. `rate = net / ai_hours` понимается в USD-пересчёте: `net_usd = net / rate`
   (net — ставка на руки после комиссии платформы: fixed — 10% мин. $5
   в валюте заказа, hourly — 10% без минимума).
4. `value_score = clamp(0..100, usd_rate / TARGET_HOURLY × 100)`.
   TARGET_HOURLY подставляется кодом в системный промпт (default $20/ч).

Пороги (код пересчитает score сам и принудительно сделает PASS, если score
ниже минимума — арифметике модели не доверяем):

- **< 30 (BID_MIN_SCORE)** → PASS всегда.
- **30–60** → BID. Ставка — около **середины вилки**, не выше.
- **> 60** → BID. Всё равно не выше середины вилки (широкая вилка —
  середина диапазона, а не верх).

**Ориентир конкурентоспособности: ~$10/ч на руки** (середина рынка для
нового аккаунта сейчас). Если середина вилки даёт сильно больше — отлично,
ставь середину. Если середина вилки даёт меньше $10/ч — это уже зона
риска, взвешивай остальные факторы.

**Реальность свежести (не переоценивай ранний отклик):** система видит
заказ через секунды после публикации. `bids = 0` НИЧЕГО не значит — в
следующие минуты заказ получит десятки откликов, и большинство будет
ближе к середине и низу вилки. Ставка по верху вилки гарантированно
проигрывает таким конкурентам. Никогда не ориентируйся на верх вилки.

**Модификаторы value_score (±, применяй как смещение оценки, не как veto):**

- `prepaid_milestone` или `is_escrow_project` — клиент платёжеспособен, деньги
  задепонированы: +5 к score (готовность брать чуть дешевле компенсируется
  надёжностью оплаты).
- Заказ свежий (младше ~30 минут по `submit_ts`): +5 (ранний отклик —
  преимущество сам по себе).
- Клиент с подозрительной историей (если видно из описания/контекста): −10.

**Пол:** итоговая ставка не ниже 70% от середины вилки бюджета — ниже пола не
опускайся даже ради score. Пол вычисляется и принудительно применяется кодом
в валюте заказа.

### Политика апгрейдов

- **sealed** — всегда, кроме заказов с `hidebids=true` (уже запечатан).
- **Первая пятёрка (`bids <= 5`)** — ТОЛЬКО sealed. Highlight и sponsored
  запрещены.
- **Позиции 6–10 (`5 < bids <= 10`)** — на усмотрение модели: highlight если
  net >= $100 в USD-эквиваленте (пересчёт по курсу из бюджета); sponsored если
  net >= $200 эквивалент И (`prepaid_milestone` ИЛИ `is_escrow_project` ИЛИ
  `upgrades.featured`) И цена <= $5 (0.75% от ставки, мин $1.90).

### Политика этапных платежей (milestones)

На платформе есть этапные платежи: работодатель вносит деньги на этап
(они блокируются), исполнитель по готовности запрашивает_release_ — деньги
уходят исполнителю. API это поддерживает (проверено 04.10.2026):
`POST /projects/0.1/milestone_requests/` (запрос этапа: project_id, bid_id,
amount, description) → работодатель принимает → этап создан и профинансирован.

Когда выгодно предлагать разбивку на этапы в тексте отклика:

- **fixed и ставка >= ~$150** — предлагай 2–3 этапа (типово 30–40% старта /
  остаток по приёмке). Клиент видит контроль риска, мы не сидим на полном
  обязательстве до конца.
- **Клиент без верификации оплаты / без депозита** — этапная оплата почти
  обязательна в предложении: 30–40% предоплата до старта, иначе полный риск
  неоплаты на исполнителе.
- **Мелкие заказы (< ~$100)** — один этап в конце, не усложняй: лишняя
  бюрократия отпугивает.
- Hourly-заказы — этапы не предлагай (там почасовая оплата сама по себе).

Автоматической отправки запросов этапов код пока не делает — после назначения
исполнителя запрос создаём вручную через API/сайт.

### 2. Стек

- **Ядро (брать уверенно):** React, Next.js, TypeScript, Spring Boot,
  PostgreSQL, Docker, HTML/CSS.
- **1–2 чужих, но известных элемента** (Python, FastAPI, Node.js, Express) —
  НЕ основание для PASS. Письмо пиши уверенно, без акцента на пробелах, без фраз
  вроде «я не знаю X».
- **Полностью чужой стек** — PASS: Flutter, React Native, .NET, Unity,
  PHP/WordPress/CMS-конструкторы, мобильная разработка, дизайн-only.
- **Cryptocurrency-проекты — всегда PASS**: категория требует верификации
  аккаунта Freelancer (Verified), наш аккаунт не верифицирован — API отклонит
  ставку с 403 RESTRICTED_FROM_BIDDING_PREMIUM_VERIFIED_JOB (проверено
  04.10.2026). Не трать цикл скоринга на них.
- **Recruiter-проекты (`upgrades.recruiter=true`, бейдж RECRUITER) — всегда
  PASS**: доступны только Preferred Freelancer, наш аккаунт не подходит
  (подтверждено скриншотом сайта 04.10.2026). Код режет такие ставки до POST.
- Чистый дизайн без кода (UI/UX, «design only») — PASS.

### Контекст bids-ресурса

В user message код передаёт `bids_balance` и `next_bid_in_minutes`:

- Баланс 1–2 и долгий реген (более ~12 ч) — поднимай планку: пограничный
  value_score 60–75 → PASS. Ставка — на самые очевидные заказы.
- Баланс unknown — планку не меняй.

### Объём-ловушка

Дёшево ≠ мелко. Считай часы (opt/real/pess в поле `hours`). Не исключай
объёмные заказы только из-за цены — решение делает value-score.

### Материалы заказа (обязательны к анализу)

В JSON заказа приходит `artifacts` — распарсенные приложенные файлы и страницы
по ссылкам из описания (код скачивает и извлекает текст сам). Всегда учитывай
их содержимое при оценке часов и подводных камней: это часть требований
клиента, а не необязательное чтение. Плейсхолдер про бинарный файл (PDF/DOCX)
означает, что содержимое не извлечено — закладывай в оценку время на его
изучение при старте.

## Техника: публичный JSON API проектов

Эндпоинт (тот, что использует сам сайт; работает без авторизации):

```
GET https://www.freelancer.com/api/projects/0.1/projects/active/
```

### Рабочие параметры (проверено)

| Параметр | Что делает | Пример |
| --- | --- | --- |
| `query` | Булев поиск: `AND OR NOT` (капс), `"точная фраза"`, `(скобки)` | `spring AND boot NOT python` |
| `jobs[]` | Скиллы по ID | `jobs[]=9&jobs[]=2370` |
| `project_types[]` | `fixed` или `hourly` | `project_types[]=fixed` |
| `languages[]` | Язык проекта | `languages[]=en` |
| `sort_field` | `submitdate` (свежие) | `submitdate` |
| `limit` | Максимум 100 | `100` |
| `full_description` | `true` — полный текст описания | `true` |
| `compact` | Облегчённый JSON (всегда включать) | `true` |

Ответ: `result.projects[]` + `result.total_count`.

### Поля проекта под скоринг

- `id`, `title`, `description`, `seo_url`
- `type` + `budget{minimum,maximum}`, `currency{code, exchange_rate}`
- `bid_stats{bid_count, bid_avg}`
- `submitdate` (unix), `bidperiod`, `language`
- `upgrades{featured, sealed, NDA, urgent, recruiter, fulltime}`
- `active_prepaid_milestone`, `is_escrow_project`, `hidebids`

### Этикет и устойчивость

- Заголовок `User-Agent` обычного браузера — с пустым часть CDN режет.
- Эндпоинт внутренний/неофициальный: может измениться → держать fallback.
- Автосабмит ставок: официальный bids API с OAuth — допустим по ToS при
  использовании официального API.

## Ставка через официальный API

```
POST https://www.freelancer.com/api/projects/0.1/bids/
Headers: Freelancer-OAuth-V1: <token>, Content-Type: application/json
Body: {project_id, bidder_id, description, amount, period, milestone_percentage}
```

`amount` — в валюте проекта; `period` — дни; `milestone_percentage` — 100.
