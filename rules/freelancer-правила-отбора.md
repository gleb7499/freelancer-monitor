# Freelancer.com — Правила отбора заказов и сборка поисковых URL/API (единый источник правды)

> Дата: 2026-09-29. Платформа активная (Upwork — закрытый этап; аккаунт с 148 Connects висит резервно, не удалять).
> Парсер: публичный JSON API (`/api/projects/0.1/projects/active/`), HTML-дампы не нужны.
> Ниши: см. список_ниш.md. Этот файл — только правила и техника поиска.
> Значения в таблицах вынесены так, чтобы их можно было менять одной правкой.
> Всё, что помечено «проверено», тестировалось вживую 2026-09-29.

## Все правила

| Правило | Значение | Где применяется |
| --- | --- | --- |
| Оплата клиента | верифицирована (payment verified + deposit made на странице заказа, блок About the Client) | Ручной просмотр (API верификацию клиента в выдаче не отдаёт) |
| Bids у заказа | 0–15 | Клиентский фильтр по `bid_stats.bid_count` |
| Бюджет / ставка | **не фильтруются кодом** — ни минимального бюджета, ни минимальной ставки. Оценка целесообразности цены (дёшево/дорого относительно объёма и конкуренции) — задача LLM-скоринга | LLM-скоринг |
| Явный фуллтайм | пас | Клиентский фильтр по `upgrades.fulltime` |
| Сортировка выдачи | от новых к старым (`sort_field=submitdate`) | URL/API |
| Возраст заказов | только свежая выдача (bidperiod обычно 7 дней) | URL/API |
| История клиента (отзывы, траты) | без истории — ок | Ручной просмотр |
| Рейтинг клиента | не ниже 4 (если рейтинг есть; если нет — осознанный компромисс на старте для первых отзывов) | Ручной просмотр |
| Жалобы в отзывах клиента | минимальное количество | Ручной просмотр |
| Открытые заказы у клиента | ≤ ~10 открытых → ок; больше или hire rate < ~40% → пас; явно непонятные — выдавать с советами, решение за человеком | Ручной просмотр |
| Бесплатные тесты | запрещены | Ручной просмотр |
| Объём-ловушка | дёшево ≠ мелко; считать часы (опт/реал/песс). Не исключать — выдавать с оговорками и подводными камнями, решение за человеком | Ручной просмотр |
| Язык заказа | английский (`languages[]=en`); остальные — пас | URL/API + ручной просмотр |
| Гео клиента | любой страны — ок (на Freelancer гео меньше значит, чем на Upwork); при желании фильтр `countries[]=XX` (ISO) | URL/API |
| Senior-опыт / узкий домен без моего опыта | пас (для Next.js-ниши — junior/mid-задачи брать, senior SSR-архитектуру без опыта — пас) | Ручной просмотр |
| Чистый дизайн без кода (UI/UX, «design only») | пас — заказы для дизайнеров | Ручной просмотр + NOT-фильтры |
| Мобильная разработка (React Native / Flutter / native), просочившаяся мимо NOT-фильтров | пас | Ручной просмотр |
| Дедлайн короче 7 дней при объёме более 30 ч | показывать с оговоркой «+дни до контракта» | Решение при отклике |
| Пограничные / неясные случаи | показывать всегда; скрывать только при явном НЕТ — решение за человеком | Решение при отклике |
| Оценка времени | оптимистичный / реалистичный / пессимистичный | Решение при отклике |
| Ставка при биде | бюджет как есть, не торгуемся; hourly — середина вилки (может ближе к низу). Платёж на руки = bid − 10% (мин. $5): bid $140 → $126. Скидка 10–25% — по открытым заказам + hire rate клиента | Решение при отклике |
| Ресурс ставок | 6 bids/мес (free), восполнение 1 bid / 120 ч. Режим снайпера: ставка только на заказ, прошедший все фильтры. Лимит расхода — примерно 1 ставка в 2–3 дня | Решение при отклике |

---

> **Бюджет не фильтруется кодом.** Раньше действовали полы «Ставка от $15/ч» и «Бюджет от $50» — отменены. Код отсекает только детерминированное (дедуп, bids, язык, fulltime, свежесть, сроки), а пригодность заказа по цене целиком решает LLM-скоринг: дешёвые (в т.ч. INR) заказы доходят до модели и оцениваются по соотношению цена/объём/конкуренция.

## Про границу bids

В отличие от Upwork (бакеты «10 to 15»), API отдаёт **точное** `bid_stats.bid_count` — порог держим ровно ≤ 15, бакетной логики не нужно. Бонус: `bid_stats.bid_avg` — средняя ставка конкурентов, полезно при ценообразовании.

## Карта поиска: публичный JSON API

Эндпоинт (тот, что использует сам сайт; работает без авторизации):

```
GET https://www.freelancer.com/api/projects/0.1/projects/active/
```

### Рабочие параметры (все проверено)

| Параметр | Что делает | Пример значения |
| --- | --- | --- |
| `query` | Булев поиск: `AND OR NOT` (капс), `"точная фраза"`, `(скобки)` | `spring AND boot NOT python` |
| `jobs[]` | Скиллы по ID; повторяется для нескольких | `jobs[]=9&jobs[]=2370` |
| `project_types[]` | `fixed` или `hourly` | `project_types[]=fixed` |
| `languages[]` | Язык проекта | `languages[]=en` |
| `countries[]` | Страна клиента, ISO 3166 | `countries[]=DE` |
| `sort_field` | `submitdate` (свежие), `bid_count`; дефолт — релевантность | `submitdate` |
| `reverse_sort` | `true` — обратный порядок | `true` |
| `limit` | Записей на страницу, максимум 100 | `100` |
| `offset` | Пагинация | `100`, `200`, … |
| `full_description` | `true` — полный текст описания вместо превью ~200 символов | `true` |
| `compact` | Облегчённый JSON (всегда включать) | `true` |

Ответ: `result.projects[]` + `result.total_count`.

### Молча игнорируются (проверено — фильтровать на своей стороне)

`min_budget`, `min_avg_price`, `min_avg_hourly_price`, `featured` — параметры принимаются, фильтрации нет. Всё это есть в объекте проекта для клиентского скоринга.

### Поля проекта под скоринг

- `id` — дедуп и история виденного (sqlite)
- `title`, `preview_description` / `description` (с `full_description=true`)
- `seo_url` → линк дословно: `https://www.freelancer.com/projects/{seo_url}` (не реконструировать)
- `type` + `budget{minimum,maximum}` или `hourly_project_info`
- `bid_stats{bid_count, bid_avg}`
- `submitdate` (unix), `bidperiod`, `language`
- `currency{code, exchange_rate}` — пересчёт не-USD в USD
- `upgrades{featured, sealed, NDA, urgent, recruiter, fulltime, pf_only, ip_contract}`
- `active_prepaid_milestone` — клиент уже депонировал деньги (сильный плюс)

### Справочник скиллов

```
GET https://www.freelancer.com/api/projects/0.1/jobs/   → 3483 скилла {id, name}
```

ID по имени искать один раз и хардкодить. Актуальные ID твоего набора: 9 JavaScript, 323 HTML5, 607 PostgreSQL, 741 Git, 759 React.js, 979 Typescript, 1002 Docker, 1042 CSS3, 2370 Spring Boot, 2376 Next.js, 2703 REST API. Java — найти через справочник.

### Пример боевого запроса

```
https://www.freelancer.com/api/projects/0.1/projects/active/?query=(spring%20OR%20react%20OR%20next)%20AND%20NOT%20wordpress%20NOT%20shopify&jobs[]=2370&jobs[]=759&jobs[]=979&project_types[]=fixed&languages[]=en&sort_field=submitdate&full_description=true&compact=true&limit=100
```

### Этикет и устойчивость

- Заголовок `User-Agent` обычного браузера — с пустым часть CDN режет.
- Паузы 5–8 с между страницами; для живого мониторинга — опрос раз в ~60 с.
- Эндпоинт внутренний/неофициальный: может измениться → держать fallback на HTML-дампы.
- Автосабмит ставок через API — запрещён (ToS, бан). Пайплайн: агент ищет/скорит/пишет черновик → человек жмёт Place Bid.

## Как правила связаны с нишами

- Позиционирование: fullstack-связка **React + Spring Boot** — козырь (фронт и бек одним исполнителем), приоритет в скоринге. Потом отдельные frontend-заказы (React/Next/вёрстка из Figma), потом backend/REST API. Bugfix-ниши на голую Java не заводить — мусора много.
- Каждая ниша получает свой `query` в синтаксисе API + набор `jobs[]` из своих скиллов + клиентские фильтры из «Всех правил».
- Исключения чужого стека обязательны (в `query` через `NOT`): `php, laravel, python, django, ruby, rails, .NET` — чужой backend; `wordpress, shopify, webflow, wix, squarespace, elementor, bubble, framer, opencart` — низкобюджетные конструкторы; `"react native", flutter` — мобильная разработка; `tester, testing, QA` — QA-шум; `designer, "UI/UX", logo, branding` — дизайн; `video, UGC, unity, 3d` — медиа/геймдев; `solana, solidity, "smart contract"` — senior-крипта. DeFi/Web3-фронтенд НЕ исключён — решение за человеком.
- Слово `mobile` в вёрсточных нишах НЕ исключаем (mobile-friendly — предмет заказа); отсекаем только `flutter OR "react native"`.
- Слово `java` НЕ исключаем в fullstack-нишах — токенизация цепляет JavaScript, и fullstack-заказы помечены обоими.
- Правила уровня «Ручной просмотр» применяются к любой выдаче любой ниши.
