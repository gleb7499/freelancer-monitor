## Все правила (универсальные)

| Правило | Значение | Где применяется |
| --- | --- | --- |
| Оплата клиента | верифицирована | Фильтр |
| Отклики у заказа (proposals / bids) | 0–10; больше 10 — жёсткий отсев кодом, до LLM и человека не доходит (для Freelancer; Upwork-часть этого файла не используется) | Фильтр |
| Ставка (hourly) | от $15 | Фильтр |
| Бюджет (fixed) | от $50 | Фильтр |
| Явный фуллтайм | пас | Фильтр |
| Сортировка выдачи | от новых к старым | Фильтр |
| Возраст заказов | только свежая выдача | Фильтр |
| Язык заказа | английский — ок, остальные — пас | Фильтр / ручной просмотр |
| История клиента (отзывы, траты) | без истории — ок | Ручной просмотр |
| Рейтинг клиента | не ниже 4 (если рейтинг есть; если рейтинга нет — клиент тоже подходит, осознанный компромисс на старте для набора первых отзывов) | Ручной просмотр |
| Жалобы в отзывах клиента | минимальное количество | Ручной просмотр |
| Открытые заказы у клиента | ≤ ~10 открытых + hire rate ≥ ~60% → ок; > ~10 открытых или hire rate < ~40% → пас. Явно нет только те, что кричат об этом. В остальном — выдавать в итоговой выборке с советами человеку | Ручной просмотр |
| Бесплатные тесты | запрещены | Ручной просмотр |
| Объём-ловушка | дёшево ≠ мелко; считать часы. Не исключать из выборки — предлагать с оговорками и конкретными подводными камнями, окончательное решение за человеком | Ручной просмотр |
| Senior-опыт / узкий домен без моего опыта | пас (для Next.js-ниши — junior/mid-задачи брать, senior SSR-архитектуру без опыта — пас) | Ручной просмотр |
| Чистый дизайн без кода (UI/UX, «design only») | пас — заказы для дизайнеров, не для разработчика | Ручной просмотр |
| Мобильная разработка (React Native / Flutter / native iOS/Android), просочившаяся мимо NOT-фильтров | пас | Ручной просмотр |
| Дедлайн короче 7 дней при объёме более 30 ч | показывать в выборке, но с оговоркой «+дни до контракта» | Решение при отклике |
| Пограничные / неясные случаи (нужно читать описание из страницы деталей заказа) | показывать всегда; скрывать только при явном НЕТ по правилам — решение за человеком | Решение при отклике |
| Оценка времени | оптимистичный / реалистичный / пессимистичный | Решение при отклике |
| Ставка при биде | Всегда со скидкой, минимум 10% от базы (база = min(середина вилки, средняя ставка конкурентов)). Глубже при высокой конкуренции (число откликов, средняя ставка), мягче при prepaid/депозите и свежем заказе. Пол — 70% от середины вилки | Решение при отклике |

## Отклонения платформ

Где платформы расходятся с универсальными правилами или друг с другом:

| Аспект | Upwork | Freelancer.com |
| --- | --- | --- |
| Верификация оплаты | фильтр `payment_verified=1` | API верификацию клиента в выдаче не отдаёт — только ручной просмотр (payment verified + deposit made) |
| Число откликов | бакеты «менее 5 / 5–10 / 10–15», граница 0–15 по верху бакета | точный `bid_count`, код отсекает bids > 10 до LLM |
| Уровень фрилансера | tier 1–2 | нет такого фильтра |
| Гео клиента | любой страны — сразу нет | любой страны — ок (гео меньше значит, чем на Upwork) |
| Платёж на руки | — | bid − 10% (мин. $5): bid $140 → $126 |
| Ресурс ставок | connects | 6 bids/мес (free), восполнение 1 bid / 120 ч; режим снайпера — ставка только на заказ, прошедший все фильтры |
| Позиционирование | продаём вёрстку сайтов, стек — инструмент; ведущий блок — вёрстка (ниши 1–4), React — усиление | fullstack-связка React + Spring Boot — козырь и приоритет в скоринге, потом frontend, потом backend |

Детали и механика каждой платформы — в её файле.

## Как правила связаны с нишами

- Каждая ниша из `список_ниш.md` получает поисковый запрос (строгий + широкий) и набор фильтров из секции «Все правила» (уровень «Фильтр»); механику сборки под конкретную площадку — из её файла.
- Исключения чужого стека обязательны во всех запросах: `php, laravel, python, django, ruby, rails` — чужой код; `wordpress, shopify, webflow, wix, squarespace, elementor, bubble, softr, carrd, framer, showit, readymag, gohighlevel, opencart` — низкобюджетные конструкторы/платформы; `"react native", flutter` — мобильная разработка, не профиль; `tester, testing, QA` — QA-заказы, просачивающиеся через dev-запросы; `designer, "UI/UX", logo, branding` — дизайн-заказы; `video, UGC, unity, "3d"` — медиа/геймдев-шум; `solana, solidity, "smart contract"` — senior-крипта. DeFi/Web3-фронтенд сознательно НЕ исключён — решение по домену за человеком. Исключение из исключений: ниша 4 (Bitrix24/CMS) — там интеграция в движок и есть предмет заказа.
- В вёрсточных нишах (1–3) слово `mobile` НЕ исключаем (адаптив/`mobile-friendly` — предмет вёрстки); отсекаем только `flutter OR "react native"`.
- Слово `java` НЕ исключаем (токенизация цепляет Java↔JavaScript, fullstack-заказы помечены обоими) — детали в [синтаксис_запросов.md](синтаксис_запросов.md).
- Конструкторы (`wordpress, webflow, wix, squarespace, elementor`) исключены в нишах сайтов/вёрстки: там преимущественно дешёвые заказы с «своим админом». Если в выборке регулярно всплывают дорогие заказы на тему/плагин — можно обсудить отдельную пассивную нишу.
- Блок D (Spring Boot, ниши 12–13) имеет **свои NOT-группы**: frontend-слова там не исключаются, отсекаются чужие backend-стеки (`php, python, django, ruby, rails, laravel, .NET`). JavaScript там не исключаем — токенизация цепляет Java↔JavaScript. Java/Spring bugfix-ниша исключена — даёт слишком много мусора.
- Правила уровня «Ручной просмотр» применяются к любой выдаче любой ниши на любой платформе.
